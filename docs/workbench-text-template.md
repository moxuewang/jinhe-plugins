# 工作台工具模板

把 `examples/workbench-text/plugin.json` 和 `examples/workbench-text/index.html` 放在 ZIP 根目录，即为可导入的最小工具。先修改清单的全局唯一 `id`、名称、作者、描述和版本；沿用实际 `main/glyph/category/accepts/acceptsMultiple` 字段。这个模板是开发示例。

页面只需编辑文本。宿主在 HTML 最前面注入现有 `JH`，示例没有引入其他脚本，没有注册旁路接口。HTML 内的 JavaScript 使用 ES5 语法和 Promise，可直接编辑；这两个运行文件没有额外脚本依赖。

下一正式版 **1.8.62+** 新增可选清单字段 `acceptsMaterialIds:true`（默认false）：表示工具会通过 `launchParams` 的材料ID读取完整原件。它与 `acceptsMultiple` 分开；单输入工具只设前者，仍只接一份。宿主给这样的HTML直接传ID，长文本不再塞入旧150000字符直传参数。旧HTML缺省仍走原text兼容与长度拒绝，原生工具保持旧行为。

本模板同时保留 `acceptsMultiple:true`，因为它确实完整处理多份有序材料；因此在已有多材料交接版本中，未知新字段即使被忽略，仍可沿既有ID路径运行。不能为了让单输入工具取长文本而虚报多输入能力；此类单输入模板需要1.8.62+宿主。

完整流程是：用户选工作台材料 → 根据清单核类型、可读状态与大小 → 按选择顺序 `take(id)` → 文本只读 `type:text` 的 `text`；文件只读返回的 `path`，用 `file.info/readChunk` 严格解码 UTF-8 → 用户确认用两个换行拼接并替换文本 → 编辑 → `put({type:'text',text,name})` → 保存返回的真实 `id` → `targets([id])` → 用户选一个返回的目标 → `send([id],target.id)`。

| 实际约定 | 模板处理 |
|---|---|
| `workbench.list()` 返回数组；`onChange` 收到 `{items:[...]}` | 分开解析，不假定两者同形；监听更新不能被更早的 list 回调盖回去。 |
| `take` 给完整原文，`preview` 只是摘要 | 从不把列表预览当输入。先核元数据，避免把超大引用文件先复制进私有目录再拒收。 |
| `take` 文件路径可能为 `filesDir` 下绝对路径，也可能为 `workbench_in/` 相对路径 | 原样交给 `JH.file`，不改写路径、不猜 URI、不使用 fetch/XHR。 |
| 单条复制上限为 `32*1024*1024` 字节 | 每份与最终文本都核实际 UTF-8 字节；最多16份，合计32MiB（含分隔换行）。超限拒绝，不截断、不静默丢材料。 |
| 短分块不等于 EOF | 64KiB 请求允许合法短回话，按实际字节推进；未到已知 EOF 却返回空块、文件大小变化或坏 UTF-8 均失败。BOM 保留。 |
| 多输入与长文本按材料 ID 交接 | 清单诚实声明 `acceptsMultiple:true`，接收全部有序 ID；过多/重复/无效 ID 明确失败。兼容旧 `text` 分享参数。 |
| `onChange` 返回退订函数 | 取消选择、开始读取、页面离开都退订；每次任务有代际，取消/关闭后的旧回话不能替换文本或继续链式调用。 |
| `put` 可返回已有材料 ID（`merged:true`） | 只用确认返回的 ID。更改文本后作废旧发送状态，必须重新保存，不向猜测的目标 ID 发送。 |
| `targets/send` 可能因卸载、删除、不可读而失败 | 目标由宿主现查，明确选择，失败保留文本、当前弹窗和可重试操作。空名单如实显示。 |

取消选择或读取不会 `put`、不会持久化编辑。`take` 本身可能按宿主约定复制一份材料到工具私有目录，这与“保存回工作台”不同；示例不删除宿主交回的文件。已经发出的 `put/send` 不能由网页回滚，所以保存与发送期间不显示“取消读取”；关闭页面只让迟到回调失效，不伪称已撤回原生请求。

这个模板通过“编辑文本”给作者保留处理入口。替换处理算法时，应继续保留完整原文、预算、错误恢复与确认步骤。只有实际能处理的材料类型才能写入 `accepts`；若只做文本，改为 `['text']` 并删除文件分支；若删掉多输入逻辑，也应删 `acceptsMultiple:true`。

必要反例覆盖：超过旧8MiB的完整材料、精确32MiB/多1字节、多材料拼接换行预算、未选最新项、缺失/变类型材料、超大引用在 take 前拒绝、跨UTF-8边界的短读/坏编码/空块/大小变化、取消与关闭后的晚回调、退订、保存失败/缺ID/合并ID、编辑后旧ID失效、接收工具卸载、目标清单为空。不要用仅替换 `JH` 的同步假对象声称做过 Android 实测。

现有接口仍有一个公开边界：`onChange` 内部注册请求没有向作者暴露 Promise 或确认回话；模板使用返回的退订函数及代际保护，不虚构监听确认接口。原生页面销毁时也会摘除监听。


## 多窗口条件保存（下一正式版 1.8.62 起）

`JH.storage.compareAndSet(key, expected, value)` 可保护同一存档的并发修改。键、新值必须为字符串；预期值为字符串或 `undefined`（仅匹配不存在）。空串与不存在不同；`null`、数字和布尔值均 reject `bad_args`。新值按 UTF-8 计最多 1 MiB，超限 reject `too_large`。

返回 `{ok:true,swapped:true,bytes}` 才确认本次匹配并提交；`{ok:true,swapped:false}` 表示已被其他窗口修改，不写入也不回显原值。提交或读回未确认时 reject `write_failed`；错误、超时均不能证明没有提交。保留完整候选并允许导出，再重新读取确认；不要自动以候选覆盖新版本。

预期值必须来自本次编辑所基于的原始快照；保存前重新读取并替换预期值，会把旧候选覆盖到别人的新版本上。成功后可用本次确认提交的候选更新自己的基准。

它与旧 `set/remove` 共用宿主队列和互斥锁，只保证单键比较与修改。旧 `set` 仍可随后无条件覆盖；没有多键事务、自动合并或断电保证。旧宿主用 `typeof JH.storage.compareAndSet === 'function'` 检查；缺失时暂停写入并允许导出，不以 `get→set→get` 冒充原子提交。清单没有最低版本新字段。本工作台文本模板不持久化编辑，无需调用此方法。
